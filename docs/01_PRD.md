## 1 專案背景與目標

### 1.1 背景
集團各公司、各部門文件散落於個人電腦、Email、BPM 系統，缺乏統一的知識沉澱與分享平台，造成：
- 重複造輪子，相同問題反覆排查
- 人員離職後知識流失
- 跨部門知識難以共享

### 1.2 目標
建立一套**集團級知識庫系統**，支援：
- 文章撰寫（Markdown，支援插入圖片）與附件上傳
- 樹狀目錄管理（公司別 → 部門 → 自訂目錄，最多 6 階）
- 標籤分類與全文關鍵字搜尋
- **AI 輔助**撰寫、校正、問答（本地端 Ollama）
- 即時協作編輯感知（WebSocket）
- @提及同仁通知系統
- 版本歷史與回滾
- 細粒度權限控制（整合現有 BPM 帳號系統）

### 1.3 成功指標
| 指標 | 目標值 |
|------|--------|
| 文章搜尋回應時間 | ≤ 500ms（關鍵字） |
| AI 回應首 Token 時間 | ≤ 3s（本地 Ollama） |
| 系統可用率 | ≥ 99.5%（工作時段） |
| 檔案上傳單檔上限 | 5 MB |

## 2 使用者角色

角色由 BPM 登入 API 回傳的 `級職` 欄位自動對應，不另建帳號體系。

| 角色代碼 | 名稱 | BPM 對應條件 | 說明 |
|---------|------|------------|------|
| `GUEST` | 訪客 | 未登入 | 僅可瀏覽公開文件 |
| `MEMBER` | 一般同仁 | 登入後，級職 < 主管門檻 | 可瀏覽部門文件、建立文章/附件、留言 |
| `MANAGER` | 部門主管／經理 | 登入後，`主管工號` 有值 或 級職 ≥ 主管門檻（待定義） | MEMBER 基礎上，可編輯本部門他人文章 |
| `ADMIN` | 系統管理員 | 手動於後台指定 | 全權管理 |

> **主管判斷邏輯**：若 BPM 回傳資料中，此人的 `員工工號` 等於某人的 `主管工號`，則視為主管；或由 ADMIN 手動升級。

## 3 BPM 整合說明

### 3.1 登入 API 回傳欄位說明

```json
{
  "組織名稱": "碩禾電子材料",
  "組織OID": "aae8e849cdd2100486ce62c68f92dc43",
  "員工工號": "GV112001",
  "員工姓名": "蔣佳緯",
  "員工Mail": "harryjiang@gigasolar.com.tw",
  "職稱": "一般人員",
  "級職": 9,
  "主要部門": 1,
  "部門代碼": "S1800",
  "部門名稱": "資訊服務部",
  "主管工號": "S094009",
  "主管姓名": "鄭智寬",
  "主管電子郵件": "eric@gigasolar.com.tw"
}
```

### 3.2 系統內部欄位對應

| BPM 欄位 | 系統用途 |
|---------|---------|
| `組織OID` | 公司唯一識別，作為目錄第一層 key |
| `組織名稱` | 目錄第一層顯示名稱 |
| `員工工號` | 系統內使用者 ID（主鍵） |
| `員工姓名` | 顯示名稱 |
| `員工Mail` | @提及時顯示，通知用 |
| `部門代碼` | 目錄第二層 key |
| `部門名稱` | 目錄第二層顯示名稱 |
| `主管工號` | 判斷是否為主管（比對員工工號） |
| `級職` | 輔助判斷角色（MEMBER vs MANAGER） |

### 3.3 同仁列表 API
- 系統需能呼叫 BPM API 取得同部門同仁列表，用於：
  - 文章編輯權限指派
  - 留言 @提及下拉選單
- API 格式待 BPM 負責人確認；前端呼叫後快取至 Redis（TTL：1 小時）

#### 5.1.3 主內容區（Main）
- 路由切換後呈現對應頁面元件，預設為 `/home`

### 5.2 首頁 /home

#### 5.2.1 搜尋區
| 元素 | 說明 |
|------|------|
| 關鍵字查詢輸入框 | 全文搜尋文章標題 + 內文；去抖動 300ms；命中後左側目錄樹節點高亮 |
| 標籤選取 | 多選標籤篩選；與關鍵字並用（AND 邏輯） |
| AI 模式按鈕 | 開啟右側彈出視窗，進行自然語言問答（RAG 模式） |

#### 5.2.2 通知卡片區
首頁主內容區分為兩個區塊：

**A. 未讀通知（待查看）**
- 當有人在文章留言中 `@` 提及目前登入者，自動產生一張通知卡片
- 卡片顯示：文章標題、留言摘要（前 50 字）、留言者姓名、時間
- 點擊卡片 → 跳轉至 `/article/:id` 並自動展開評論面板，且定位至該則留言
- 點擊「已查看」按鈕 → 卡片移至已讀區，通知標記為已讀

**B. 已讀通知**
- 顯示近 30 天內已標記查看的通知卡片
- 可快速點擊再次跳轉至文章

### 5.3 目錄樹結構

#### 5.3.1 層級定義

```
第 1 層（系統固定）：公司別（來源：BPM 組織名稱 / 組織OID）
  第 2 層（系統固定）：部門（來源：BPM 部門代碼 / 部門名稱）
    第 3–8 層（使用者自訂）：目錄節點，最多 6 階
      └── 文章節點 / 附件節點
```

> 第 1、2 層由系統根據 BPM 資料自動建立，不可手動新增或刪除。
> 第 3 層起為使用者自訂目錄，支援 6 階深度（即樹深最多 8 層）。

#### 5.3.2 垃圾桶目錄
- 每個**公司**下有一個固定的「🗑 垃圾桶」目錄（系統建立，不可刪除）
- 文章 / 附件下架（`is_published = false`）時，自動移入垃圾桶目錄
- 垃圾桶目錄中的內容不顯示於搜尋結果
- ADMIN 可在管理員設定 → 垃圾桶管理中執行永久刪除

#### 5.3.3 目錄操作
| 功能 | 權限 | 說明 |
|------|------|------|
| 建立目錄節點 | MANAGER、ADMIN | 輸入名稱，選擇父節點，最多 6 階自訂深度 |
| 拖曳更換父節點 | MANAGER（本部門）、ADMIN | 拖曳後須確認；留下操作紀錄 |
| 重新命名 | MANAGER、ADMIN | 即時編輯節點名稱 |
| 刪除目錄節點 | ADMIN | 需確認；子節點移至「未分類」 |
| 更換分類 & 標籤結構 | ADMIN | 批次編輯標籤與目錄關聯 |

### 5.4 文章 /article/:id

#### 5.4.1 URL 參數直接查看
- 路由格式：`/article/:id`（例：`/article/42`）
- 支援分享連結：複製 URL 給他人，對方登入後可直接開啟該文章
- 若 `id` 不存在或無權限，顯示對應錯誤頁

#### 5.4.2 建立 / 編輯文章欄位

| 欄位 / 功能 | 類型 | 說明 |
|------------|------|------|
| 文章標題 | 文字輸入框 | 顯示於目錄樹節點名稱 |
| Markdown 編輯器 | 左編輯 / 右預覽 雙欄 | 支援 GFM、程式碼高亮、**插入圖片** |
| 所屬目錄 | 多選（彈出浮動視窗） | 可加入多個目錄節點 |
| 標籤 | 多選 + 即時建立 | 輸入不存在的標籤自動新增；Checkbox 勾選 |
| 附件 | 多選（彈出 /Attachment 元件） | 可關聯已有附件，或直接上傳新附件（≤5MB） |
| 是否公開 | Radio（公開 / 部門私有） | 公開：所有登入者可見；部門私有：限所屬部門 |
| 文件上架 | Radio（上架 / 下架） | 下架後移至垃圾桶目錄，**資料庫不刪除** |
| 文章編輯權限 | Checkbox 多選（彈出浮動視窗） | 指定可編輯同仁；資料來源：BPM API；主管以上預設可編輯 |
| 建立日期時間 | 系統自動 | 唯讀 |
| 編輯日期時間 | 系統自動 | 每次儲存後更新，唯讀 |

#### 5.4.3 Markdown 圖片插入
- 編輯器工具列提供「插入圖片」按鈕
- 使用者選取本機圖片（JPG、PNG，≤5MB）→ 上傳至 Docker Volume
- 後端回傳圖片 URL → 自動插入 Markdown `![alt](url)` 語法
- 圖片渲染：預覽區與查看模式均可正常顯示

#### 5.4.4 儲存機制
- **批次 HTTP POST**：按「儲存」時，差異資料批次 POST 至後端
  - 支援 axios retry interceptor（最多重試 3 次）
- **自動草稿**：每 60 秒將編輯中內容暫存至 `sessionStorage`

#### 5.4.5 版本歷史與回滾
- 每次按下「儲存」後，系統自動寫入一筆版本快照：
  - 欄位：`version_number`（遞增）、`content_snapshot`（完整 md 內容）、`diff_summary`、`editor_id`、`saved_at`
- 點擊「修改紀錄」按鈕 → 右側彈出視窗：
  - 列出所有版本（版本號、儲存者、時間、diff 摘要）
  - 每筆版本右側提供「預覽」與「回滾至此版本」按鈕
- **回滾行為**：
  - 回滾後視為產生新的儲存，舊版本不覆蓋（版本號遞增）
  - 回滾需二次確認對話框
  - 寫入一筆紀錄：「XXX 將文章回滾至 v{n}」

#### 5.4.6 評論功能
- 任何已登入者均可留言
- 點擊「評論」按鈕 → 右側彈出視窗查看 / 新增留言
- **@提及功能**：
  - 輸入 `@` 時跳出同仁選單（資料來源：BPM 同仁列表 API）
  - 提交後觸發通知系統（詳見第 8 章）
- 留言顯示：留言者姓名、時間、內容
- 被 @提及者的留言卡片顯示「未讀」標記，點擊「已查看」後移至已讀

#### 5.4.7 AI 輔助（詳見第 6 章）
- AI 提示詞輸入框 + 勾選上傳資料（md 內文 / 附件）
- AI 產出 Markdown 預覽，詢問是否套用
- AI 校正按鈕：校正後詢問是否套用

## 6 AI 功能需求

> 使用本地端 **Ollama**，預設模型：`qwen3:6b`（可於管理員設定調整）

### 6.1 AI 問答模式（首頁 AI 模式）
- 右側彈出視窗輸入自然語言問題
- 系統將問題 + RAG 召回文章片段送給 Ollama
- 以 SSE 串流逐字回傳答案
- 回答下方顯示引用來源（文章標題 + `/article/:id` 連結）

### 6.2 AI 產生文章
- 輸入提示詞 + 可選上傳現有 md 內容 / 附件作為上下文
- SSE 串流回傳 Markdown
- 前端預覽，詢問是否套用至編輯器

### 6.3 AI 校正文章
- 將編輯器內容送 AI 進行：中文文法校正、Markdown 格式整理、重複段落提示
- 回傳校正後 Markdown，詢問是否套用

### 6.4 Embedding 與 RAG
- 每次文章儲存後，非同步對全文產生 Embedding，存於 DB 向量欄位
- AI 問答時進行語意相似度 Top-K 召回，作為 Prompt 上下文

## 7 協作與即時功能

### 7.1 即時編輯感知（WebSocket）
- 進入文章編輯頁時，加入該文章的 WebSocket room
- 若有他人正在編輯，顯示提示：「{姓名} 正在編輯此文章」
- 離開或關閉頁籤時，自動發送 leave 事件
- **不實作 OT**，以感知提示為主，避免衝突覆蓋

### 7.2 批次儲存（HTTP POST）
- 儲存使用批次 HTTP POST，非 WebSocket，確保穩定
- axios retry interceptor（最多 3 次，指數退避）
- 後端回傳最新 `version_number`，前端比對衝突

## 8 通知系統

### 8.1 觸發條件
| 事件 | 通知對象 |
|------|---------|
| 留言中 @提及某人 | 被提及者 |

### 8.2 通知流程
1. 使用者在留言中輸入 `@{姓名}` 並送出
2. 後端解析 @ 對象的員工工號，寫入 `notifications` table
3. 被提及者下次進入首頁時，通知卡片出現在「未讀通知區」
4. 被提及者在文章的評論面板點擊「已查看」→ 通知標記為已讀，卡片移至「已讀通知區」

### 8.3 通知卡片顯示內容
| 欄位 | 說明 |
|------|------|
| 文章標題 | 超連結，點擊跳轉至 `/article/:id` |
| 留言者姓名 | 誰 @了你 |
| 留言摘要 | 留言前 50 字 |
| 時間 | 相對時間（例：「3 小時前」） |
| 狀態標記 | 未讀 / 已讀 |

### 8.4 已讀通知
- 顯示近 30 天已讀通知
- 超過 30 天自動隱藏（資料庫保留，不刪除）

## 9 權限矩陣

| 操作 | GUEST | MEMBER | MANAGER | ADMIN |

## 10 非功能性需求

### 10.1 效能
| 項目 | 目標 |
|------|------|
| 文章關鍵字搜尋 P95 | ≤ 500ms |
| 文章頁首次載入 | ≤ 1.5s |
| 單次儲存 API | ≤ 800ms |
| AI 串流首 Token | ≤ 3s（視硬體） |

### 10.2 安全性
- 所有 API 須攜帶 JWT Token（來自現有登入 API）
- Token 儲存於 **`sessionStorage`**（非 `localStorage`）
  - 關閉瀏覽器視窗 → Token 清除 → 下次需重新登入
  - 開新分頁（Tab）→ sessionStorage 不共享 → 需重新登入
- 敏感操作（永久刪除、回滾）須二次確認對話框
- 附件上傳驗證 MIME type，僅允許：`.doc`, `.docx`, `.xls`, `.xlsx`, `.pdf`, `.jpg`, `.png`, `.txt`

### 10.3 Session 策略
| 行為 | 結果 |
|------|------|
| 關閉瀏覽器視窗 | 需重新登入 |
| 開啟新分頁（Ctrl+T） | 需重新登入 |
| 重新整理頁面（F5） | 維持登入（sessionStorage 保留） |
| Token 過期（TTL 8hr） | 自動跳轉登入頁 |

### 10.4 檔案儲存（Docker Volume）
- 所有上傳的附件與 Markdown 圖片儲存至 Docker Volume（掛載於 `/app/uploads`）
- 目錄結構：`/uploads/{組織OID}/{部門代碼}/{年月}/{檔案UUID}.{副檔名}`
- 靜態檔案由 Express 的 `express.static` 提供服務，路徑加入 JWT 驗證 middleware
- Docker Volume 名稱：`kb_uploads`

### 10.5 可用性
- Vue Router 懶加載，首頁包大小 < 200KB gzip
- 目錄樹虛擬捲動（超過 200 節點時啟用）
- 語系：**繁體中文**（不支援多語系）

### 10.6 資料保護
- 下架文章 / 附件：資料庫標記 `is_published = false`，**不實際刪除**，移入垃圾桶目錄
- 永久刪除：僅 ADMIN 可執行，連同 Docker Volume 中的檔案一併刪除
- 修改紀錄與版本快照：永久保留
- 通知紀錄：永久保留（首頁僅顯示近 30 天已讀）
